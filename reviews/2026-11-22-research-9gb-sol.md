# Draft concept: an own-encoded ~9 GB GGUF of Inkling 2 Mini for a 16 GB Mac

## Model
- thinkingmachines/Inkling-2-Mini, 26.07 B params, looped MoE: 24 layers, layers 6-17 are the looped core, default P = 3 passes, so 48 layer visits. 128 routed experts per layer in two tensors: ffn_gate_up_exps (2304 inputs) and ffn_down_exps.
- Quality metric: mean KL to a Q8_0 reference at P = 3 (llama-perplexity --kl-divergence). S = selection set (WikiText-2 test text), T1 = held-out prose, T2 = held-out reasoning traces (GSM8K, model-generated). Differences are paired over chunks with bootstrap 95% CI.

## Landscape near 9 GB (HF file sizes)
- Unsloth: UD-IQ1_S 7.76 GB, UD-IQ1_M 8.02, UD-IQ2_XXS 8.49, UD-Q2_K_XL 9.14 (9,138,715,328 B), UD-IQ3_XXS 11.66.
- AtomicChat: AD-IQ2_XXS-Q2 7.90, AD-IQ2_M 8.67, AD-IQ2_XXS 10.43.
- bartowski: smallest is IQ2_XXS 10.32 GB. Many other repos not yet checked (APEX variants, GSQ-RCO, NInfer repacks of UD).
- UD-Q2_K_XL tensor types (from its header): gate_up IQ1_S in layers 0-4 and 6, IQ2_XXS in 5, 7, 12-14, IQ2_XS in 8 and 10, IQ2_S in 9, 11, 15-23. down: Q2_0 in 0-4, 6, 12-14, 21-23; NVFP4 in 5, 7-11, 15-19; MXFP4 in 20. Attention mostly Q8_0 / Q6_K, output Q4_K, embeddings IQ4_XS. Its imatrix: "imx_s0.conv.jsonl", 8238 chunks (conversation data).
- Stock llama.cpp's Metal backend cannot multiply NVFP4, so those tensors run on the CPU. The sibling measured UD-IQ3_XXS (20 NVFP4 expert tensors) at 68 t/s prompt and 10.9 t/s generation versus about 225 / 19 t/s for all-Metal files of similar size on an M5 Pro. Unsloth's own llama.cpp fork already runs NVFP4 on Metal.

## Measured so far (this repo and the sibling repo, same metric)
1. At UD-IQ2_XXS's exact per-tensor types, plain llama-quantize with an imatrix (M0) is +0.02727 KL behind UD on S. UD's edge by tensor class: gate_up 61%, non-expert 23%, down 15%. The edge is the encoder, not the type map or the imatrix (three imatrices differ by < 0.0004).
2. Attenuation: fits that lower per-layer MSE shrink each row's output gain <q,w>/<w,w> below 1, and over 48 visits this costs KL. A mean-aware gate_up scale refit lowered full-Gram error in 128/128 experts and still raised KL by +0.072 (gain 0.79). The same refit with each row restored to llama-quantize's own gain gained -0.0038. Rescaling our Q2_0 down from gain 0.86 to 1 gained -0.0070. Gain 1 is not universal: it hurt gate_up and UD's own Q2_0 down (gain 0.90).
3. Our best own file at 8.49 GB (M0rk: mean-aware gate_up refit + gain restore, gain-1 Q2_0 down, all tensors in Metal types) closes 40% of the gap to UD on S. Held out: M0rk minus UD-IQ2_XXS +0.01424 on T1, +0.01662 on T2; it beats both AtomicChat files on both sets (-0.016 to -0.041).
4. The sibling's full-Gram code refinement (changes grid indices and signs, keeps scales, objective tr(E H E^T) with H = Gram + 0.1 diag shrink, gain floor per row) for IQ2_S / IQ3_XXS gate_up at 11.6 GB: closes 93% of the gap to UD-IQ3_XXS on S, 74% on T1, 18% on T2. Its Grams are WikiText-2 train only (same source as S), about 5k tokens per median expert for 2304 dims. The refiner does not support IQ1_S, IQ2_XXS or IQ2_XS.
5. Sibling's block map (one block of experts quantized, rest at reference, S): looped blocks and the last block are the most sensitive at 2 bits; per-layer KL B1 (0-5) 0.0046, B2 (6-11) 0.0104, B3 (12-17) 0.0142, B4 (18-19) 0.0180, B5 (20-23) 0.0167.
6. The sibling's 11.5 GB file (v1) is public: it failed its gate against UD-IQ3_XXS and was released as the closest-to-original all-Metal file under 12 GB, 1.75x faster generation than UD-IQ3_XXS on stock llama.cpp.

## Proposed plan for the 9 GB tier
- Target: one own-encoded GGUF, every tensor in a type stock llama.cpp runs on Metal, size <= 9,138,715,328 B (UD-Q2_K_XL), so it fits a 16 GB Mac's default GPU memory with room for context.
- Step 0: landscape. List every GGUF of this model in 8.0-9.2 GB on HF with its types and off-Metal tensor count. Score UD-Q2_K_XL and any all-Metal comparator on S, T1, T2. Measure stock-llama.cpp speed of ours vs UD-Q2_K_XL.
- Step 1 (baseline M1): llama-quantize at UD-Q2_K_XL's per-tensor types, with each NVFP4 down replaced by IQ4_NL (same 4.5 bpw, on Metal). Check size and that MXFP4 runs on Metal.
- Step 2 (M1rk): apply the M0rk recipe (mean-aware gate_up refit with per-row gain restore; Q2_0 down rescaled to gain 1).
- Step 3 (M1rr): the sibling's full-Gram code refiner on the 11 IQ2_S gate_up layers, with Grams captured on mixed calibration (prose, chat, reasoning traces) and more tokens, then the gain restore.
- Step 4: spend any bytes left under the limit by the block map (looped and last blocks first).
- Gate: lower KL than every all-Metal file <= the limit on T1 and T2 (CI below 0), and report the difference to UD-Q2_K_XL whatever it is. A held-out T3 for the final file.
- Release bar (open, for the owner): only own encodings. Is "best all-Metal own encoding at this size + faster than UD on stock llama.cpp" enough, as for the sibling's v1, or must it beat UD-Q2_K_XL?

- Stock llama.cpp types only (the file must run in stock llama.cpp, LM Studio, Ollama).

## 2. Exact layouts and refiner search

**2.1 — Verified.** All three formats cover 256 weights per block and start with fp16 `d`. Every grid index selects **eight ordered weights**. For the layout below, words are interpreted little-endian, and byte zero of a 64-bit grid entry is the first lane. `IQ2_XXS` and `IQ2_XS` use grid magnitudes `{8,25,43}` and the same 128-entry `ksigns_iq2xs` table. For a seven-bit code `s`, the eight-bit mask is `s | (parity(s) << 7)`. A set mask bit negates that lane, so each group has an even number of negative signs. The parity constraint applies independently to each eight-weight group. [Block structs](https://github.com/ggml-org/llama.cpp/blob/master/ggml/src/ggml-common.h#L355-L400), [sign table and IQ2 grids](https://github.com/ggml-org/llama.cpp/blob/master/ggml/src/ggml-common.h#L474-L590), [decoders](https://github.com/ggml-org/llama.cpp/blob/master/ggml/src/ggml-quants.c#L2346-L2394)

| Point | Format | Verified layout and decode | Inferred candidate count at fixed scales |
|---|---|---|---|
| 2.2 | `IQ2_XXS` | **66 B**, `d` followed by `uint16_t qs[32]`, interpreted as eight 8-byte records. In each 32-weight record, bytes 0–3 are four indices into the 256-entry `iq2xxs_grid`. The next LE32 word holds four 7-bit signs at offsets `0,7,14,21`, then scale nibble `a` at bits 28–31. Decode each lane as `d*(a+0.5)/4 * grid_lane * sign`. [Decoder](https://github.com/ggml-org/llama.cpp/blob/master/ggml/src/ggml-quants.c#L2346-L2370), [grid](https://github.com/ggml-org/llama.cpp/blob/master/ggml/src/ggml-common.h#L521) | **32,768 per 8** = 256 grids × 128 even-parity signs. |
| 2.3 | `IQ2_XS` | **74 B**, `d`, `uint16_t qs[32]`, then `uint8_t scales[8]`. Each word has a 9-bit index into the 512-entry `iq2xs_grid` in bits 0–8 and a 7-bit sign code in bits 9–15. Each scale byte covers 32 weights. Its low nibble covers the first 16, and its high nibble the next 16. Decode uses the same `d*(a+0.5)/4` multiplier. [Decoder](https://github.com/ggml-org/llama.cpp/blob/master/ggml/src/ggml-quants.c#L2372-L2394), [grid](https://github.com/ggml-org/llama.cpp/blob/master/ggml/src/ggml-common.h#L587) | **65,536 per 8** = 512 grids × 128 even-parity signs. |
| 2.4 | `IQ1_S` | **50 B**, `d`, `uint8_t qs[32]`, then `uint16_t qh[8]`. Each `qh` covers 32 weights. Bits 0–11 supply three high index bits per group of eight, at offsets `0,3,6,9`. Each corresponding `qs` byte supplies the low eight bits. Bits 12–14 store scale `a`. Bit 15 selects `δ=+1/8` when clear and `−1/8` when set, shared by all four groups. The 2,048-entry `iq1s_grid` supplies signed trits in `{-1,0,1}`. Decode is `d*(2*a+1)*(trit+δ)`. The grid encodes the trits directly, with no parity field or independent lane sign mask. [Decoder](https://github.com/ggml-org/llama.cpp/blob/master/ggml/src/ggml-quants.c#L2498-L2519), [grid and delta](https://github.com/ggml-org/llama.cpp/blob/master/ggml/src/ggml-common.h#L1086-L1094) | **2,048 per 8** at fixed `δ`. With four fixed indices, a shift update has **2 candidates per 32**. A joint exact update of all four indices and the shared shift has `2 × 2048⁴` encoded combinations. |

**2.5 — Inferred.** For the full-Gram refiner, use exact **group coordinate minimization**. Set `r=q−w`, maintain `u=Hr`, and for a group `g` score the replacement `z` with `2(z−q_g)ᵀu_g + (z−q_g)ᵀH_gg(z−q_g)`. After accepting a move, update `u += H[:,g](z−q_g)`. This retains cross-group information in the linear term. It gives an exact minimum for the selected group with the other groups fixed. [GPTQ quadratic reconstruction objective](https://arxiv.org/abs/2210.17323), [decoder-defined candidate sets](https://github.com/ggml-org/llama.cpp/blob/master/ggml/src/ggml-quants.c#L2346-L2519)

**2.6 — Inferred.** The cheapest straightforward exhaustive scan I would implement uses unscaled codewords `v` and caches `vᵀH_ggv` for each expert and group position. For either IQ2 format, `v` and `−v` are both legal and have the same quadratic term. Score one representative using the absolute linear term and recover the winning orientation from its sign. That takes **16,384 pair scores** for `IQ2_XXS` and **32,768** for `IQ2_XS`. If a gain constraint makes only one orientation feasible, use that orientation’s signed score. For `IQ1_S`, absorb the fixed shift into the linear term, scan **2,048 trit vectors**, then optionally test the shared shift as a separate 32-weight move. Batch rows against tiled codebooks to reuse the quadratic terms. A sign match followed by one parity repair can solve the sign subproblem for diagonal `H_gg` at fixed magnitudes. With a full `H_gg`, off-diagonal interactions can change the winning sign pattern. [Sign and grid tables](https://github.com/ggml-org/llama.cpp/blob/master/ggml/src/ggml-common.h#L474-L590), [IQ1_S decoder](https://github.com/ggml-org/llama.cpp/blob/master/ggml/src/ggml-quants.c#L2498-L2519)

**2.7 — Verified.** The stock search functions are `quantize_row_iq2_xxs_impl`, `quantize_row_iq2_xs_impl`, and `quantize_row_iq1_s_impl`. The IQ2 implementations choose signs with parity repair, try scales, and use the grid map and `iq2_find_best_neighbour_cached` for off-grid patterns. IQ1_S searches weighted ternary thresholds and both shift directions, then maps each group onto the grid using `iq1_find_best_neighbour2` where needed. These are weighted encoder searches with no full input Gram argument. [IQ2_XXS search](https://github.com/ggml-org/llama.cpp/blob/master/ggml/src/ggml-quants.c#L3194), [IQ2_XS search](https://github.com/ggml-org/llama.cpp/blob/master/ggml/src/ggml-quants.c#L3374), [IQ1_S search](https://github.com/ggml-org/llama.cpp/blob/master/ggml/src/ggml-quants.c#L4382)

## 3. Full-Gram calibration with sparse expert coverage

**3.1 — Verified.** Stock GPTQ adds `0.01 * mean(diag(H)) * I` by default. QMoE used **0.1 relative identity damping** for numerical robustness on Switch models and used rounding for the few Hessians that still failed inversion. QMoE groups experts for compute but forms a separate Hessian for each. In MoEQuant’s three-bit comparison, the GPTQ-based method with expert-balanced sampling and affinity guidance moved average accuracy from **35.85 to 36.47** on DeepSeekMoE-16B and **45.03 to 49.75** on Mixtral-8x7B versus QuaRot+GPTQ. These studies provide evidence for damping and coverage, with different models and objectives from Inkling’s fixed-grid refit. [GPTQ implementation](https://github.com/IST-DASLab/gptq/blob/main/gptq.py#L96-L103), [QMoE §3.1](https://proceedings.mlsys.org/paper_files/paper/2024/file/c74b624843218d9b6713fcf299d6d5e4-Paper-Conference.pdf), [MoEQuant Tables 3–5](https://proceedings.mlr.press/v267/chen25aa.html)

**3.2 — Inferred.** Test **diagonal shrinkage first** on one sensitive looped `IQ2_S` layer. For the same captured tokens and initial weights, compare `(1−λ)H_e + λ diag(H_e)` at `λ=0, 0.1, 0.3, 0.6, 1`. Preserve the diagonal so high-energy input channels retain their weight as off-diagonal terms shrink. Record the exact formula for the sibling run. `H + 0.1 diag(H)` is equivalent, up to a positive scalar, to **λ ≈ 0.091** in the convex formula. `H + 0.1 mean(diag(H)) I` is identity damping and changes the objective differently. Select on held-out KL as well as held-out local error. [GPTQ damping](https://github.com/IST-DASLab/gptq/blob/main/gptq.py#L96-L103), [QMoE robustness modifications](https://proceedings.mlsys.org/paper_files/paper/2024/file/c74b624843218d9b6713fcf299d6d5e4-Paper-Conference.pdf)

**3.3 — Inferred.** Test **pooled shrinkage** for `gate_up` using a leave-one-expert-out pool from the **same physical layer and loop pass**. Normalize the pool to the expert’s trace, or borrow the pooled correlation matrix and restore the expert’s diagonal. Use stronger shrinkage for experts whose separate document shards yield unstable Grams or held-out errors. `down` sees each expert’s own intermediate coordinates, so use diagonal shrinkage as its starting point. **Verified:** classical Ledoit–Wolf estimates shrinkage toward a scaled identity for covariance estimation. **Inferred:** use it as a baseline with an explicitly uncentered second moment for the raw layer reconstruction objective. Default centering would discard the mean-output error term. I found no measurement that establishes pooled shrinkage or Ledoit–Wolf as the best choice for this MoE refit. [Inkling expert tensor shapes](https://github.com/ggml-org/llama.cpp/blob/master/src/models/inkling2.cpp#L130-L136), [Ledoit–Wolf paper](https://www.ledoit.net/honey.pdf), [estimator and centering docs](https://scikit-learn.org/stable/modules/generated/sklearn.covariance.LedoitWolf.html)

**3.4 — Verified.** Calibration domain can move GPTQ results. In *Quantization Meets Reasoning*, changing WikiText-2 calibration to generated Numina-Math reasoning data raised average benchmark accuracy by a reported **9.8 points** for three-bit GPTQ on DeepSeek-R1-Distill-Qwen-1.5B. *When Calibration Data Matter* reports gains from targeted calibration for two-bit GPTQ at 70B and smaller mean responses for single-pass GPTQ in its smaller dense-model panel. **Inferred:** at a fixed token budget, compare prose-only to a `1/3` prose, `1/3` chat, `1/3` reasoning pilot. Accumulate normalized `H[e, pass, domain]` separately and combine them explicitly, so a document-rich domain or hot pass cannot silently set the mixture. Keep calibration prompts and trace sources disjoint from evaluation. Preserve naturally routed assignments and log quota shortfalls. [Reasoning study, Table 2](https://openreview.net/pdf?id=BM192Ps5Nv), [sub-four-bit calibration study](https://arxiv.org/abs/2611.11079), [MoEQuant sampling](https://proceedings.mlr.press/v267/chen25aa.html)

**3.5 — Inferred.** **5,000 assignments for 2,304 inputs is 2.17× the width.** An uncentered Gram needs at least 2,304 linearly independent rows for full rank. Repeated tokens across passes, correlated tokens from the same document, and affinity weighting can all reduce effective coverage. Use **5k, 10k, and 20k assignments per expert** as pilot checkpoints, with 10k as a first collection target if time permits. These are experimental budgets. Use the lower tail of expert coverage, pass/domain counts, and held-out error stability to decide whether to collect more. With 8 of 128 routes, 10k assignments per expert **per pass** takes about 160k input tokens at uniform routing. Rare experts can take more. For scale, a single layer’s 128 dense fp32 `2304×2304` Grams occupy **2.53 GiB**, so shard or process them by layer. **Verified:** published dense GPTQ sample-count curves and QMoE coverage experiments do not establish a transferable per-expert minimum for this objective. [Inkling routing](https://thinkingmachines.ai/model-card/inkling-2-mini/), [dense calibration-size ablation](https://arxiv.org/html/2311.09755#S4.SS2), [QMoE calibration discussion](https://proceedings.mlsys.org/paper_files/paper/2024/file/c74b624843218d9b6713fcf299d6d5e4-Paper-Conference.pdf)
