## High severity

1. **`lib.sh:34–35, score` — the advertised chunk limit is a silent no-op.** `score … S --chunks 8` passes the flag, but the local KL implementation takes `n_chunk` from the reference `.kld` and iterates over that count. The saved `mix-early-S8` log demonstrates the numerical consequence above. Use an eight-chunk reference or implement the limit in the KL loop, then require the log’s observed chunk count to equal the requested count. [Saved run](logs/ppl-mix-early-S8.log:5) · [KL implementation](vendor/llama.cpp/tools/perplexity/perplexity.cpp:1675)

2. **`c1.sh:9,22` and `splice.py:118` — a stale or incomplete file qualifies as a completed build.** Change the imatrix, BF16 source, donor, fitting code, or `m0rk-mix.json` and rerun. C1 regenerates its JSON but reuses any existing layer donors and `c1.gguf`. Interrupting the splice also leaves a file at the final path, and a truncated file passes the upper size bound. The script can hash and score an old build under the new recipe. Fingerprint the dependencies, build and verify at a unique temporary path, and publish atomically. Check completion under the build lock. [Resume logic](scripts/c1.sh:9) · [Splice writer](../inkling-2-mini-quant/scripts/splice.py:118)

3. **`lib.sh:29–31, score` — the cache key can identify different bytes as the same run.** Replace a model or reference with a same-size file and preserve its mtime, or rewrite it within the same timestamp second. The previous KL is returned. Changing a loaded llama/ggml dylib while leaving the executable untouched also preserves the key. C1 computes a SHA-256, but `score` never uses it. Key on model and reference content digests, scorer build identity including its libraries, and the effective argument vector with argument boundaries preserved. [Cache key](scripts/lib.sh:30)

4. **`lib.sh:30–37, score` — the signature, scored files, and log are sampled at different times.** A job signs model A, waits for the GPU, then opens the same pathname after another process replaces it with B. It writes B’s KL with A’s signature. Separately, a writer truncates the public log while the previous `.sig` remains readable, and releases the GPU before writing the new `.sig`. A concurrent cache reader can accept that mismatched pair. Score immutable input paths, recheck the cache inside a per-run lock, and publish the validated log and signature as one generation. [Score and publication order](scripts/lib.sh:30)

5. **`lib.sh:34–35, score` — trailing arguments can override the model or reference named by the wrapper.** `score test A.gguf S -m B.gguf` passes two model options. The local parser assigns the later path, while the signature fingerprints A and records B only as argument text. Replacing B can then return a cached KL for its previous contents. The same issue applies to `--kl-divergence-base`. Reject overrides of identity-defining options, or resolve the effective invocation first and fingerprint its actual inputs. [Wrapper](scripts/lib.sh:34) · [Model option handler](vendor/llama.cpp/common/arg.cpp:3036)

6. **`lib.sh:29–35` and `c1.sh:29–38` — dataset labels and paired baselines have no checked provenance.** Put T1’s `.kld` at the S reference path. KL mode reads the evaluation tokens from that `.kld`, so passing `-f data/S.txt` still produces a T1 evaluation labelled S. The comparison then looks up baselines by run name and checks only array shape. S and T1 both have 16 chunks here, so unrelated chunks can produce a plausible paired interval. Bind each result to the reference model, ordered token/chunk digest, context and loop count, and require those fields to match before pairing. [KL token reader](https://github.com/ggml-org/llama.cpp/blob/master/tools/perplexity/perplexity.cpp) · [Pairing code](analysis/compare.py:24)

7. **`lib.sh:31–38` and `c1.sh:25,30,38` — failed evaluations and reports can return success.** A truncated `.kld` can make llama-perplexity print an error and return from its KL routine without a final KL. `score` signs the fresh log anyway and ends with a successful `echo`. Its cache check also accepts a bare `Mean KLD` match without parsing a finite value. Later, a missing comparison row raises `KeyError`, but `/bin/sh` sees `tee` succeed and can print `c1 done`. Validate the final finite KL, top-1 and expected chunk sequence before signing. Check each producer’s status before publishing its output, including the SHA file. [Score checks](scripts/lib.sh:31) · [Report pipelines](scripts/c1.sh:25)

8. **`splice.py:118` — an output alias can destroy a source model.** Pass the base as `OUT`, or use a symlink or hard link to a donor. Opening `OUT` with `"wb"` truncates the inode backing the live source mappings. The build can then fail on a mapped read after destroying the input. Check existing output identity against every input with `samefile`, write a separate temporary inode, and rename only after verification. [Output open](../inkling-2-mini-quant/scripts/splice.py:118)

9. **`assemble.py:78–85, plan` — companion expert scales are selected by the donor’s nickname.** Only gate-up level `"ud"` brings its `.scale`. A custom per-layer gate-up donor produced by `degain2.py` can contain both the weight and its scale, yet assembly copies only the weight. Down donors never bring their scale. With donor scale 2 and an unscaled base, the assembled expert runs at half its intended amplitude, and `--verify` passes. Resolve each selected weight and its optional scale together, including replacing or dropping any inherited scale. [Donor selection](scripts/assemble.py:78)

10. **`degain2.py:20,28–30` — `--target-from` ignores the reference expert’s `.scale`.** If the reference’s raw decode has row gain 0.5 and its expert scale is 2, its effective target gain is 1. The script targets 0.5. Load the reference’s scale independently of the source’s scale and apply it before computing the target dot product. [Target calculation](scripts/degain2.py:28)

11. **`meanfit.py:121–142` — scaled source experts are fitted in the wrong units.** For a source with `.scale[e] = 2`, the runtime weight is `2 * decode`, while the fit minimizes error for `decode` against BF16. The donor also omits the companion scale. The resulting scale bits can worsen the runtime objective even when the printed error improves. Include the expert multiplier in the unit-code vectors and preserve its tensor, or reject scaled inputs explicitly as `refine-codes.py` does. [Fit driver](scripts/meanfit.py:121)

12. **`degain2.py:26–36` — the row target is neither enforced nor verified.** A row with `q = w/8` has gain 0.125 and can reach 1 exactly by multiplying `d` by 8. The `gain > 0.2` guard silently leaves it alone. Above the cutoff, the elementwise check can still pass a large gain error. I reproduced a two-block row with BF16 reference entries `(1,1)` and decoded contributions `(1000,−999)`. Target 0.8 gives factor 1.6, fp16 rounds the contributions to `(1600,−1598)`, `allclose` passes, and the output gain is **1.0**. Recompute gain per row from the written scales, adjust representable scales or report the miss, and distinguish zero-norm and unreachable rows. [Rescale and assertion](scripts/degain2.py:26)

13. **`lib.sh:12–16,48–51` — stale-lock removal can delete a live owner’s lock.** Two waiters read the same dead PID. A removes the stale file and acquires a new lock. B then executes its already-decided `rm -f`, deleting A’s lock, and acquires one itself. Both start heavy work. The same interleaving exists for CPU and GPU and in the sibling implementation. Use one shared kernel-backed lock protocol across both repositories, without unlinking the lock inode during acquisition. [Local lock](scripts/lib.sh:12) · [Sibling lock](../inkling-2-mini-quant/scripts/gpu-lock.sh:12)

## Medium severity

14. **`lib.sh:10–22,46–55` — shell PID ownership does not track the heavy job’s lifetime.** Kill the wrapper while its GPU child survives and a waiter can reclaim the lock over the running job. Two background subshells can also share `$$` and both pass the “already ours” check. Conversely, a crash between creating and populating the file leaves an empty lock that these waiters never reclaim. Have the actual workload hold the lock descriptor for its lifetime. Require benchmarks to take the same lock, since `pgrep` cannot exclude a benchmark that starts immediately after the check.

15. **`lib.sh, cpu_take/gpu_wait` — actual callers acquire the two locks in opposite orders.** `fit16.sh` can hold CPU while waiting for GPU, while the sibling’s `bench-v2r.sh` holds GPU while waiting for CPU. Both PIDs remain live, so neither makes progress. Provide one acquire-both helper and use the same order in both repositories. [CPU-first caller](scripts/fit16.sh:11) · [GPU-first caller](../inkling-2-mini-quant/scripts/bench-v2r.sh:9)

16. **`meanfit.py:83–89, refit_expert` — the Sherman–Morrison evaluation loses the solution on deterministic inputs.** I tested one IQ2_S block with `d=1`, zero grid indices, signs and scale levels, `v=0`, `m[0]=1`, and `w[0]=21`. The attainable optimum is level 10 with error 0. Replacing the zero diagonal by `1e-30` and subtracting the two large terms seeds level 0. Two passes reach level 2 and report **256**. Handle zero-diagonal coordinates explicitly. For positive diagonals, use the residual form based on `q − pᵀA⁻¹r`; with only 8 or 16 levels, the discrete step can also test every level of a coordinate. [Continuous solve](scripts/meanfit.py:83)

17. **`meanfit.py:79–82,101–104` — cancellation in the acceptance test can discard an exact correction.** Using the same initial block, set `m=0`, `w[0]=1`, `w[16]=3`, `v[0]=2⁶⁰`, `v[16]=1`, and other variances to zero. The original error is 4 and changing the second sub-block’s level to 1 makes it zero. I reproduced reported errors **0 and 0**, followed by retention of the original bits. Compute final acceptance and reported errors directly from the decoded residuals, `sum(v * dw²) + (m·dw)²`. [Acceptance test](scripts/meanfit.py:101)

18. **`refine-codes.py:347–362` — the gain guard ranks and accepts with numerically different predicates.** I reproduced an IQ3 group with `cur=(1,5,1,1)`, `w=(1,1,1,1)`, `H=diag(2⁶⁰,1,1,1)`, and zero accumulated gain change. The absolute-dot mask admits `(1,1,1,1)` because it loses a four-unit difference. The final delta check rejects it. The legal candidate `(1,3,3,1)` has exactly zero gain change and **ΔJ = −8**, but the row takes no move. Rank with the same `(v−cur)·uw + gch` predicate and delta objective used for acceptance, including during sign polish. [Guard and acceptance](../inkling-2-mini-quant/scripts/refine-codes.py:347)

19. **`refine-codes.py:289–312, _pick_iq3xxs_` — four-weight moves freeze each half-word’s initial parity.** The format permits a sign flip in each half of the same eight-weight word. Holding the partner fixed forever prevents that transition. With identity `H`, an all-positive minimum-grid block, and BF16 differing only in signs 0 and 4, I reproduced **zero accepted moves and J = 8**. The two-bit change is representable, reaches J = 0, and increases output gain. Add a paired cross-half flip proposal or search the whole sign word. [Candidate search](../inkling-2-mini-quant/scripts/refine-codes.py:289) · [Reference decoder](https://github.com/ggml-org/llama.cpp/blob/master/ggml/src/ggml-quants.c)

20. **`refine-codes.py:176–195,210–220` — a valid negative fp16 `d` fails validation and reverses the IQ2 target-sign rule.** I tested an IQ2_S block with `d=−1`. Its decode agrees with gguf-py, but `validate` compares an absolute magnitude with negative `db * level` and raises. The target sign proposal also assumes positive `db`. Validate with `abs(db) * level` and derive the stored sign from the signs of both the target and `db`, retaining the current code on zero-scale ties. [Validation](../inkling-2-mini-quant/scripts/refine-codes.py:176)

21. **`degain2.py:31–35` — fp16 overflow and underflow have no defined outcome.** A finite requested scale of 80,000 casts to infinity and normally aborts at the assertion. With assertions disabled, those bytes can be published. `--target inf` can even pass `allclose` on a row with entirely nonzero codes because both sides contain matching infinities. Subnormal scales can round to zero. Reject nonfinite targets, check representability before and after the cast, and handle unachievable row gains explicitly. [fp16 write](scripts/degain2.py:33)

22. **`degain2.py:17,24,39–40` — companion-scale shape and storage type are mishandled.** A scale with NumPy shape `(1,E)` makes `sc[0]` a vector and `sc[1]` invalid. An F16 scale is emitted as F32 despite the byte-preservation contract. 23. **`meanfit.py:134` and `degain2.py:18–25` — BF16 reference decoding trusts the filename.** Supply an F16 expert tensor with the correct logical shape. The scripts reinterpret its words as BF16 without an error. F16 `1.0` (`0x3c00`) becomes BF16 `0.0078125`, so both algorithms optimize against the wrong weights. Check the reference type, logical dimensions and expert count before reading its payload. [Meanfit decode](scripts/meanfit.py:134) · [Degain decode](scripts/degain2.py:24)

Expand the spec into one explicit tensor-to-donor map, rejecting overlaps or applying one documented override rule. Use that same map for sizing, writing and verification. [Planner](scripts/assemble.py:89) · [First-match writer](../inkling-2-mini-quant/scripts/splice.py:69)

25. **`assemble.py:80–97,119–124` — the size estimate omits new descriptors and changes in padding.** Adding a UD `.scale` charges its payload but reuses the base directory overhead. The new tensor-info record also occupies space, and header and tensor alignment can change. A near-limit build can be approved, written and then deleted, or a fitting build can be refused on an overestimate. Compute the aligned end offset from the exact splice plan and verify the cap on the temporary file before replacing any prior output. [Size calculation](scripts/assemble.py:94)

26. **`splice.py:59–104,133–141` — verification can certify a requested replacement that never happened.** A misspelled `--take` regex that matches zero surviving base tensors succeeds. Verification compares against the already-resolved base-only plan and records `verified=true`. Track the winning tensor names for every take and reject unintended empty selections. 27. **`splice.py:56–59,82–94, tensor_info_bytes` — only the base byte order is checked.** A big-endian donor can pass logical shape comparison, then contribute big-endian dimension/type fields and payload to a little-endian output. 28. **`gram-error.py:55–73,97–110` — float32 multiplication can erase a nonzero Gram error before float64 accumulation.** I reproduced `row_forms` returning **0** for `x=(2²⁴,1,−2²⁴)` and the all-ones Gram.
