## Reply (verbatim)

1. **G4 can pass while the main claim fails.** The candidate only has to beat UD-IQ2_XXS. If AD-IQ2_XXS-Q2 or another eligible smaller file has reliably lower held-out KL, that falsifies the same-size-or-smaller superiority claim. With \(\Delta = \mathrm{KL}_{candidate} - \mathrm{KL}_{baseline}\), a paired 95% CI wholly above zero is evidence of a loss. A CI spanning zero leaves superiority unestablished. Freeze the eligible comparator list and apply the release criterion to every file on it. Define “top-1 agreement not worse” as either a point-estimate rule or a noninferiority test with a prespecified margin.

2. **G2 can credit GPTQ for a change in the scalar quantizer, and G3 can credit it for a better byte allocation.** Compare GPTQ with a diagonal-only run of the same encoder, sharing source weights, calibration inputs, block scales or scale-selection rule, column order, and tensor types. Use the same full-Gram capture for both by zeroing the off-diagonals in the control. Score a fixed allocation and the selected allocation under both rounding methods. Those four comparisons distinguish a rounding gain, an allocation gain, and a gain that depends on their interaction. Choose the G2 block before viewing S scores.

3. **The Gram capture can hide failures on rare experts or particular visits.** Report routed sample counts per expert and visit, plus damping and the fallback for singular or undersampled Grams. Check an emitted Q2_0 tensor against direct held-out matrix multiplication after decoding it. Report both traffic-weighted error and error by visit and expert. A pooled gain can come entirely from frequent experts or the first visit. If the capture uses reference activations, state that explicitly. Later visits in the quantized model can see different inputs and expert routes, which is one reason G1 and G2 can disagree. The cited looped-transformer paper is relevant to repeated-use calibration. Applicability to the routed capture still depends on what patch 0008 accumulates. [Quantizing Looped Transformers](https://arxiv.org/abs/2609.30820)

4. **The fidelity test has reference, leakage, and uncertainty gaps.** Q8_0 logits measure agreement with the sibling conversion. Check the candidate and strongest comparator against BF16 or F16 logits on a small common slice if feasible, since Q8_0 can change close rankings. If that check is infeasible, name Q8_0 in the claim. Extend the overlap audit to T2 and across S, T1, T2, and the G1 holdout, using source document or conversation IDs where available. Bootstrap independent source groups if several chunks share a source. T2 supplies only five chunks, and 10,000 resamples cannot add independent evidence. Show all five paired differences and how the conclusion changes when each chunk is omitted.

5. **G5 measures a proxy for the target machine.** File bytes plus the sibling’s RSS overhead do not establish peak Metal allocation. Apple describes `recommendedMaxWorkingSetSize` as a performance recommendation, and the document supplies no measured value from a 16 GB Mac. Run prefill and generation that actually reach 16K on a 16 GB machine with the intended batch sizes, KV types, and offload settings. Record the device-reported recommendation, peak Metal allocation, process footprint, memory pressure and swap, and sustained decode speed. Set a minimum acceptable speed before running it. The `-p 512 -n 128` comparison measures short-context speed. If only the 48 GB Mac is available, report the memory result as a projection and leave target fit unverified. [Apple Metal documentation](https://developer.apple.com/documentation/metal/mtldevice/recommendedmaxworkingsetsize)

6. **Headers establish tensor types and sizes. The claims about encoders, placement, and novelty need separate evidence.** The two sampled experts cannot establish that all public files used diagonal-only rounding. Pin comparator revisions and hashes and date the search. The Hugging Face index already lists additional GGUF repositories whose eligibility needs checking. Verify expert placement during both prefill and decode on the patched binary, with matching runtime settings across files. A Q2_0 payload establishes a standard storage format. Runtime compatibility also depends on Inkling architecture and operator support. With no candidate or run logs supplied, the byte cap, placement, pilot numbers, and memory figures cannot be independently verified from the design. Limit the novelty wording to the methods disclosed in the releases you audited. [Hugging Face quantization index](https://huggingface.co/models?other=base_model%3Aquantized%3Athinkingmachines%2FInkling-2-Mini) · [llama.cpp Inkling support RFC](https://github.com/ggml-org/llama.cpp/issues/29491)

7. **Spend the first compute hour on a small matched comparison.** Score the eligible public baselines on a prespecified slice of S. Capture Grams only for layers 0 and 12, and compare full-Gram and diagonal-only encoding on the same held-out activations. Build one simple all-Metal allocation under the cap and score two versions that differ only in those down tensors. If the Gram version shows no credible local or model-level gain, skip the full capture and spend the remaining budget on a small prespecified allocation sweep with diagonal rounding. Freeze one winner on full S and run the same release tests. This still answers whether an under-cap file beats the audited baselines, while limiting the GPTQ conclusion to the layers tested.
